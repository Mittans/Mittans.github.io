Task 2: Using SortedSet with a BankAccount (40 m)

SortedSets aren't just limited to primitive types like ints. Everything that you can write a sorter for can be a SortedSet!

(If you don't have a copy of the BankAccount.cs class, grab this one) Now, let's go sorting BankAccounts.

BankAccount.cs

public class BankAccount(string owner, decimal balance)
{
  public string Owner { get; set; } = owner;
  public decimal Balance { get; set; } = balance;

  public decimal Deposit(decimal amount)
  {
    if (amount < 0)
    {
      throw new ArgumentException("Amount must not be negative.");
    }
    return Balance += amount;
  }

  public decimal Deposit(int amount)
  {
    return Deposit((decimal)amount);
  }

  public decimal Deposit(double amount)
  {
    return Deposit((decimal)amount);
  }

  public virtual decimal Withdraw(decimal amount)
  {
    if (amount < 0)
    {
      throw new ArgumentException("Amount must not be negative.");
    }
    if (Balance < amount)
    {
      throw new ArgumentException("Balance is less than amount");
    }
    return Balance -= amount;
  }

  public override string ToString()
  {
    string info = $"""
      Account: {nameof(BankAccount)}
      Owner: {Owner}
      Balance: {Balance:F2}
      """;
    return info;
  }
}
  1. Make at least 10 random BankAccount objects (or copy them from a previous prac).
  2. Try to initialise a SortedSet<BankAccount>. Your code should compile, but we're going to get a runtime error.

 Should look something like: Unhandled exception. System.ArgumentException: At least one object must implement IComparable.

Output

  • Screenshot of console showing the runtime error.

Alright, let's fix this by implementing our own IComparable interface for BankAccount.

Make a new class called BankComparer. Hopefully you'll remember from a previous topic on inheritance, that we can define a class that implements an interface using this syntax:

public class BankComparer : IComparer<BankAccount>

Implementing an interface means we need to write some specific functions. For IComparer, it's easy, we only need a single function: public int Compare(BankAccount x, BankAccount y).

If you're confused as to why it returns an int, it's because these Interfaces have been around since .NET 1.0 and we still need to work with this ancient spec. (C# in general is a language with a lot of historical baggage).

You take in an x and y BankAccount, and return an int that represents the order of these BankAccounts. The VS Code Intellisense gives you a good rundown:

 

Now that we're ready to go, let's write that interface!

It should be easy to compare BankAccounts based on their Balance or their Owner  because both of those types already implement their own Compare() method. Think about what you want to do if x.Balance == y.Balance, though. If you  return 0, meaning the objects are equal, SortedSet will eat the duplicate. Maybe check string.Compare(x.Owner, y.Owner) too?

Once you've written your BankComparer class, you should be able to create a new SortedSet<BankAccount> with the syntax:

var sortedBankSet = new SortedSet<BankAccount>(new BankComparer())

(Note: we provide our custom comparer as part of the SortedSet<BankAccount> constructor)

Then, perform the following tasks:

  1. Write a DisplayAccounts()that prints the SortedSet<BankAccount> info to the console.
  2. Add 10 of your BankAccount objects to your SortedSet<BankAccount> and call DisplayAccounts()
  3. Add a new high or low BankAccount and re-run DisplayAccounts()
  4. Add a duplicate BankAccount and re-run DisplayAccounts() 

Output

  • Screenshot of your BankComparer : IComparer<BankAccount> class.

 (Optional): If you have time, you can also implement the comparer directly in the BankAccount class. In this case, your BankAccount should implement IComparable<BankAccount> (not IComparer). And the function you need to write is public int CompareTo(BankAccount? other). If you do it like this, you don't even need to pass in a custom comparer in your SortedSet, C# can figure it out. Amazing, huh?

 

Task 3: Plotting data with ScottPlot (40 m)

One thing I want to do alongside our foray into data structures, is include some basic practical tasks that every developer should have some experience with.

One of these is visualising your data. Whether you want to prepare a report for the boss, or have a figure to prove your point in an academic paper, graphing your data is super helpful to translate some complex data structures into something that's easy to digest.

And while this is probably most common in datasciency languages like Python, there's no reason you can't make a nice graph using C#.

To do this we'll use ScottPlot: https://scottplot.net/quickstart/console/ Links to an external site.

First, install the package using the VS Code terminal (make sure you're in the folder with your Topic 7A .csproj file): 

Syntax is pretty simple, we make a new ScottPlot object, and provide the data for the axiis. For a Bar chart, all we need is data for the Y values.

double[] dataY = { 1, 2, 3, 4, 5 };
ScottPlot.Plot myPlot = new();
myPlot.Add.Bars(dataY);myPlot.SavePng("quickstart.png", 400, 300);

Make sure you can find your quickstart.png and it looks ok before moving on.

We can also edit the graph by setting the properties, so to change the X-axis label, we can do: myPlot.XLabel("Ranking")

For the next few steps, you might want to have the ScottPlot cookbook on Bar plots handy: https://scottplot.net/cookbook/5/Bar/ Links to an external site.

Perform the following tasks:

  1. Change the output name to Topic7A-Task3.png and the output resolution to 800x600.
  2. Add a YAxis label "Account Balance"
  3. Add an XAxis label "Ranking"
  4. Change the Label's FontSize to 20.
  5. Set your Axes margins to be: bottom: 0, top: .2
  6. Set your data source to be your SortedSet<BankAccount> Balances.
  7. Run your code and check the graph

Note that myPlot.Add.Bars() needs to take in an Array of Doubles. You might want to iterate through your SortedSet<BankAccount> and save them to a double[] variable to pass them into ScottPlot. Or you can use a LINQ Select if you want to get C# maxxed.
