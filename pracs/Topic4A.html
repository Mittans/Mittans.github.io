Link: BrokenProgram.csDownload BrokenProgram.cs

BrokenProgram.cs

public static class BrokenProgram
{
  static void Main(string[] args)
  {
    const string input = """
       23
       + 
       77
       + 
        3
       + 
      457
       * 
        2
         
      """;
    int total = 0;
    List<int> items = [];
    List<string> symbols = [];

    for (int i = 0; i < input.Split("\n").Length; i += 2)
    {
      items.Add(int.Parse(input.Substring((i * 4) + 1, 3)));

      if (i != 0)
      {
        symbols.Add(input.Split("\n")[i - 1]);
      }
    }

    foreach (var (i, value) in items.Index())
    {
      if (i == 0) { total = value; }
      else if (symbols[i - 1] == "*")
      {
        total *= value;
      }
      else
      {
        total += value;
      }
    }
    Console.WriteLine("Total was: " + total);
    Console.WriteLine("Expected total was: 1120");
    Console.WriteLine(total == 1120 ? "Your answer was RIGHT!" : "Your answer was WRONG!\nGo and fix it.");
  }
}

Given the input, your program should keep a Total and update it based on the numbers and symbol encountered.

For the above input the total should start at 23. Then a "+" symbol is encountered, so the next number, 77 should be added to the total.

The same is true for 3 and 457, leading to a total of 560.

After this, the "*" symbol is encountered, and so the total should be doubled to 1120. However, your program isn't returning the right value.

 

Use the C# debugging tools to analyse the behaviour of the program, and find and fix the errors.

Ensure you use Breakpoints and the Locals / Watch window to find to help you step through and understand the code.

You may want to create intermediate or temporary variables to assist your understanding of the program, but don't touch the input variable.

Output

  • Screenshot of a debug session in progress, showing breakpoints, the current line being debugged and variables populated in the Locals / Watch tab.
  • Go to https://www.diffchecker.com/Links to an external site. and paste the starting code on the left, and your fixed code on the right. Take a screenshot of the resulting difference.

 

Task 2: Refactor (30 m)

Now that you have a correct solution, let's turn on some code analysis tools from Microsoft to improve the code, and crank them up.

Microsoft provides a lot of good options for code analysis: https://learn.microsoft.com/en-us/dotnet/fundamentals/code-analysis/overview?tabs=net-10Links to an external site.

Open your Topic4A (or equivalent) .csproj file and change it so it looks like this.

 

Topic4A.csproj

<Project Sdk="Microsoft.NET.Sdk">

<PropertyGroup>
<OutputType>Exe</OutputType>
<TargetFramework>net10.0</TargetFramework>
<ImplicitUsings>enable</ImplicitUsings>
<Nullable>enable</Nullable>
<AnalysisMode>All</AnalysisMode>
<EnforceCodeStyleInBuild>true</EnforceCodeStyleInBuild>
<AnalysisLevelStyle>latest-all</AnalysisLevelStyle>
<AnalysisLevelDesign>latest-all</AnalysisLevelDesign>
<AnalysisLevelNaming>latest-all</AnalysisLevelNaming>
<AnalysisLevelReliability>latest-all</AnalysisLevelReliability>
</PropertyGroup>

</Project>

This turns on a number of analysis tools and sets them to "all" (very pedantic). Following this prac, you might want to set the AnalysisMode to "Recommended" and the AnalysisLevel to "latest-recommended" instead. https://learn.microsoft.com/en-us/dotnet/core/project-sdk/msbuild-props#code-analysis-propertiesLinks to an external site.

In addition to the new yellow squigglies in VS Code, try to build your project with dotnet build to see all the additional Warnings that are generated.

Armed with this new information, examine the warnings and recommendations you have recieved, and refactor your newly fixed BrokenProgram to improve general readability and address some of the warnings. Use your judgement to decide whether a warning actually needs to be addressed or not.

Reflection
